# Фаза 3 — Деобфускація коду OLX

Головна фаза. Мета — повернути коду читабельні імена. Спершу найважливіше, що треба зрозуміти як реверсеру:

## Що таке деобфускація насправді

R8/ProGuard **видаляє** оригінальні імена й замінює на `a`, `b`, `c`. Він їх **не шифрує** — оригіналу більше не існує ніде. Тому:

> Деобфускація ≠ «розшифрувати оригінал». Це = «дати коду осмислені імена заново», частково автоматично (з метаданих), частково руками.

## Два джерела автоматичного відновлення

### 1. Kotlin `@Metadata`
Kotlin вшиває в кожен клас анотацію `@Metadata` з **оригінальними** іменами property, функцій, параметрів — навіть коли байткод обфусковано. ProGuard часто її не чистить. jadx її читає й відновлює назви.

### 2. `.source`-директива
У smali лишається `.source "MapUrlSigner.kt"`. Прапор jadx `--deobf-use-sourcename` називає обфускований клас за іменем його `.kt`-файлу.

Команда, якою згенеровано мапу:
```bash
jadx olx.apk -d src_deobf --deobf --deobf-min 2 \
  --deobf-use-sourcename \
  --deobf-cfg-file olx-names.jobf --deobf-cfg-file-mode overwrite
```

Згенеровано **88 638 мапувань**: 14 672 класи, 42 661 метод, 31 305 полів.

По класах (увесь APK):
- **8 236 (56%)** відновлено **осмислено** з метаданих/source
- 6 436 (44%) лишились синтетичними (`C3528a`)

**Але** якщо дивитись тільки на код OLX (4 285 класів) і відкинути чужі бібліотеки:

| | Класів |
|---|---|
| OLX-класів усього (у мапі) | 4 285 |
| ще синтетичні | 358 |
| …з них **анонімні класи/лямбди** (`$1`, `$2`) | **358 (усі)** |

> **Висновок:** кожен іменований клас OLX має назву — або OLX лишили її самі, або jadx відновив з метаданих. Ті 358, що лишились «C####», — це анонімні замикання (лямбди всередині функцій), які **ніколи не мали імені** в коді. Деобфускація імен класів завершена настільки, наскільки це взагалі можливо.

## Як продовжити деобфускацію руками

Решта роботи — методи/поля в конкретних класах, що тобі цікаві. Технологія:

1. Відкрий клас у jadx-gui (`jadx-gui olx.apk`), завантаж мапу через **File → Open mappings** (`olx-names.jobf`).
2. Правий клік на `m13627a` → **Rename** → даєш ім'я (напр. `buildSignedUrl`). jadx оновлює всі посилання.
3. **File → Save mappings** — мапа дописується; імена переживають перевідкриття.
4. Хочеш застосувати мапу в CLI-дереві: `jadx olx.apk --mappings-path olx-names.jobf -d src_final`.

Так мапа росте інкрементально: що більше класів розумієш — то читабельніший увесь проєкт. Для rebuild це не потрібно (правки йдуть у smali), але для **розуміння** — головний інструмент.
